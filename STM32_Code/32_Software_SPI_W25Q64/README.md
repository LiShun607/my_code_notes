# 32 软件模拟 SPI 读写 W25Q64 Flash 闪存

这是我学习 SPI 通信协议的实战项目。相比 I2C，SPI 是四线制（CS, CLK, MOSI, MISO），速度更快，且支持全双工通信。我通过纯 GPIO 模拟了 SPI 模式0时序，成功驱动了 8MB 的 W25Q64 外部 Flash。

## 核心实现
- **底层时序模拟**：配置了推挽输出（SCK, MOSI, CS）和上拉输入（MISO）。实现了 `MySPI_SwapByte` 函数，在时钟的上升沿读取 MISO 数据，下降沿改变 MOSI 数据，完美契合 SPI 模式0（CPOL=0, CPHA=0）。
- **W25Q64 驱动**：
  - 提取 JEDEC ID（通过 0x9F 指令），验证通信链路，读出 `MID=EF`，`DID=4017`。
  - 封装了写使能（0x06）、读状态寄存器（0x05）等基础指令。
  - 实现了扇区擦除（0x20）、页编程（0x02）和数据读取（0x03），并严格发送 24 位（3个字节）的地址。

## 真实踩坑记录与排查
1. **写操作必须写使能**：Flash 的写和擦除属于“危险操作”，每次发送 `PageProgram` 或 `SectorErase` 之前，必须单独发送一次 `Write_Enable`（0x06）指令，否则芯片拒绝执行。
2. **等待忙状态（Busy）机制**：Flash 擦除和写入需要时间（毫秒级），如果在它忙的时候发下一条指令，会导致通信失败。我通过读取状态寄存器1的最低位（Busy位），并加了 `WaitBusy` 超时机制，防止程序死在死循环里。
3. **写入验证（页内回绕机制）**：我特意做了一个极限测试，从一页的倒数第二个位置（如 0x0000FE）开始连续写 4 个字节。结果完美验证了手册里的规定：**写入超出一页（256字节）后，地址指针不会跨页，而是回绕到本页开头（0x000000）覆盖原有数据**。而读取操作则不受限制，可以连续跨页读。

## 心得
软件 SPI 其实比软件 I2C 好写，因为它不需要处理复杂的 ACK 应答，只需要在时钟的拨动下移位就行了。通过这次实验，我深刻理解了外部 Flash 与内部 RAM 的区别（掉电不丢失，但写入前必须先擦除为 0xFF）。
