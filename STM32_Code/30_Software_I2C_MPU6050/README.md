# 30 软件模拟 I2C 读写 MPU6050 六轴传感器

这是我第一次脱离现成库，通过纯 GPIO 模拟高低电平来实现 I2C 协议，成功驱动了 MPU6050，拿到了加速度和陀螺仪的原始数据。

## 核心实现
- **底层时序模拟**：封装了 `MyI2C_Start`、`MyI2C_Stop`、`SendByte` 等函数。利用开漏输出（Out_OD）配合外部上拉电阻，实现了 SDA 线的双向通信。
- **位操作提取**：在 `SendByte` 中，利用 `(Byte << i) & 0x80` 从最高位开始依次发送；在 `ReceiveByte` 中，利用 `Byte |= (0x80 >> i)` 依次接收拼接。
- **MPU6050 驱动**：通过查阅数据手册，准确找到了 0x75 (WHO_AM_I) 寄存器验证了身份。配置了 PWR_MGMT_1 解除睡眠，并配置了最大量程（陀螺仪 ±2000°/s，加速度计 ±16g）。

## 真实踩坑记录与排查
1. **位运算写错导致全乱码**：最开始发送字节时用了 `Byte <<= i`，导致每次循环数据都在自我改变，发出去的全是乱码。后来改为每次只对比最高位，发完再 `Byte <<= 1` 才解决。
2. **读时序的 NACK**：在读寄存器的最后一步，主机必须发送非应答（NACK），告诉从机“我读完了”，否则从机会一直拽着 SDA 线不放，导致总线死锁。
3. **数据拼接问题**：原始数据是 16 位的，分为 High 和 Low 两个 8 位寄存器。拼接时必须注意正负号处理，使用 `int16_t` 强转才能正确显示反转时的负加速度。

## 心得
软件 I2C 虽然速度不如硬件快，但极其灵活，只要是有 GPIO 口的单片机都能用。亲自写一遍底层，让我彻底搞懂了时序图和物理电平之间的转换关系。
