# 31 硬件 I2C 读写 MPU6050 六轴传感器

在搞定了软件 I2C 之后，我尝试挑战了 STM32 自带的硬件 I2C (I2C2)，实现了同样的读取功能。体验就是：硬件 I2C 太难调了！

## 核心实现
- **外设配置**：配置了 PB10(SCL) 和 PB11(SDA) 为复用开漏模式。初始化了 I2C2 外设，速率设为 50kHz。
- **事件驱动（EV事件）**：使用 `I2C_CheckEvent` 来等待状态寄存器的事件（如 EV5、EV6、EV8 等）。
- **超时防卡死机制**：为了防止从机无响应导致 `while` 死循环，自己封装了 `MPU6050_WaitEvent` 函数，加入计次循环超时跳出。

## 真实踩坑记录与排查
1. **引脚配置张冠李戴**：一开始开启了 GPIOB 的时钟，引脚也选了 10 和 11，但 `GPIO_Init` 的时候手滑写成了 `GPIOA`，导致完全没波形。
2. **超时变量未初始化**：在写 `WaitEvent` 防卡死函数时，局部变量 `WaitTime` 没有赋初值，导致判断条件一直不成立，程序彻底死在初始化里，连 OLED 都不亮。

## 心得
硬件 I2C 把底层的时序交给了硬件，虽然理论上更高效，但它的标志位和事件状态非常繁琐（著名的总线锁死Bug）。这次调试极大地锻炼了我阅读标准库底层源码和排查死循环的能力。
