# 33 硬件 SPI 读写 W25Q64 Flash 闪存

在搞定了软件模拟 SPI 之后，我进一步学习了 STM32 自带的硬件 SPI 外设（SPI1）。体验下来就是：硬件 SPI 不需要手动翻转电平，只需操作寄存器，速度快且极其稳定。

## 核心实现
- **GPIO 配置**：SPI1 的 SCK(PA5) 和 MOSI(PA7) 配置为复用推挽输出（AF_PP），MISO(PA6) 配置为上拉输入（IPU）。**CS(PA4) 依然使用普通推挽输出**，用软件手动拉高拉低（避开了硬件 NSS 容易卡死的坑）。
- **SPI 模式**：配置为模式0（CPOL=Low, CPHA=1Edge），与软件 SPI 时序完全一致。
- **速率控制**：设置了 128 分频，SCK 频率大概在 562kHz，牺牲速度换取极高的稳定性。
- **数据交换**：利用标准库的 `SPI_I2S_SendData` 和 `SPI_I2S_ReceiveData`，配合 `TXE`（发送空）和 `RXNE`（接收非空）标志位，完成了主机与从机的字节交换。

##  架构设计之美（重点）
这次实验最大的收获是体验到了**底层解耦**的魅力。
我从软件 SPI 切换到硬件 SPI 时，仅仅重写了 `MySPI.c` 里面的初始化和 `SwapByte` 函数，而上层的 `W25Q64.c`（读ID、擦除、写数据、读数据等所有业务代码）**一行都没改**，直接完美跑通！
这让我深刻体会到了在工程开发中，把“硬件驱动层”和“应用逻辑层”分离的重要性。

## 踩坑与验证
- **验证方式**：依然使用上次的极限测试，从 `0x0000FE` 开始连续写入 4 个字节。结果完美复现了“页内回绕”和“跨页读取”的物理特性，读出的数据依然是 `01 02 FF FF`。
- **心得**：硬件 SPI 相比软件 SPI 开发效率极高，后续做智能小车需要读取外部字库或存图片时，硬件 SPI 绝对是首选。至此，大二上的 STM32 核心通信协议（I2C、SPI）全部通关！
